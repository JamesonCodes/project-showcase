# Project showcase instructions

This repository is a plain Markdown library of project case studies for prospective employers and teams considering project work. Keep the root README focused on that audience.

## Essential rules

- Never invent project facts, metrics, dates, or achievements. Separate measured results, estimates, and qualitative observations.
- Keep documentation status separate from the project's development status.
- Write directly in the author's voice. Avoid em dashes, repetition, unsupported claims, and filler sections.
- Distinguish personal contributions, collaborators, and AI assistance. Label real, sanitized, and synthetic examples.
- Keep credentials and confidential information out of committed content. Link source repositories and hosted demos rather than duplicating code or committing large recordings.
- After edits, verify relative links and update the root project directory when project names, paths, or documentation status change.

## Commit and push

For this repository only, commit and push each completed change unless the user says “local only.” Include only changes belonging to the task.

## Read when needed

- Before adding or substantially revising a case study, read [the authoring guide](docs/authoring.md) and [the project README template](docs/templates/project-readme.md).
- For evidence, media, or folder-organization changes, read the relevant section of [the authoring guide](docs/authoring.md).
- For small wording edits, read the affected project files; the full guide is unnecessary.
